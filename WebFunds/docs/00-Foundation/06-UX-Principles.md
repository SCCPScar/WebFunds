# UX Principles

> Good UX reduces thinking.
>
> Great UX builds confidence.

---

# Purpose

This document defines how WebFunds should behave from the user's perspective.

It does not describe screens.

It describes how every interaction should feel.

Whenever uncertainty exists during product design, these principles should guide the decision.

---

# UX Philosophy

WebFunds exists to reduce uncertainty.

Every interaction should help the owner understand their financial life with less effort than before.

The application should never require the owner to learn how it works.

The product should feel immediately familiar.

---

# The Four Questions

Whenever the owner opens WebFunds, one or more of these questions usually exists:

- How much money do I have?
- How much can I safely spend?
- What changed since I last checked?
- Does anything need my attention?

Every important screen should help answer at least one of these questions.

---

# Mental Models

Navigation follows intentions instead of technical categories.

The owner does not think:

"I need to access the transaction repository."

The owner thinks:

"I need to understand this purchase."

The interface should always follow the owner's mental model.

Never the database structure.

---

# Recognition Before Memory

The interface should minimize memory usage.

Whenever possible, users should recognize information instead of remembering it.

Examples:

- merchant logos
- category icons
- transaction previews
- recent searches
- suggested categories
- remembered locations

The application should remember details so the owner does not have to.

---

# Progressive Disclosure

Show the minimum amount of information required for the current decision.

Reveal details only when requested.

Example:

Transaction Card

↓

Transaction Details

↓

Receipt

↓

OCR Analysis

↓

Raw Data

Each step reveals additional information.

The owner should never feel overwhelmed.

---

# One Primary Action

Every screen should have one clearly dominant action.

Secondary actions must remain available but visually quieter.

The interface should never force the owner to choose between multiple equally important actions.

---

# Immediate Understanding

The owner should understand the purpose of every screen within three seconds.

If explanation is required,

the screen should be redesigned.

---

# Reduce Cognitive Load

Never ask the owner to calculate information mentally.

Instead of displaying:

Income

Expenses

Balance

Also display:

Available to Spend

The application should perform calculations.

Not the owner.

---

# Consistency

Identical actions should always behave identically.

Buttons.

Menus.

Cards.

Gestures.

Animations.

Terminology.

Predictability builds confidence.

---

# Forgiveness

Mistakes should be recoverable.

Whenever technically possible:

- support Undo
- request confirmation only for destructive actions
- preserve previous values
- avoid permanent loss of information

The owner should feel safe while exploring.

---

# Speed

Fast interactions create trust.

Common actions should require minimal effort.

Examples:

Open transaction

1 tap

Categorize transaction

2 taps

Add a memory

2 taps

Start a Financial Cycle

2 taps

Search

1 tap

---

# Search Everywhere

Search is a first-class feature.

It should find:

- transactions
- merchants
- categories
- memories
- subscriptions
- goals
- AI conversations
- financial cycles

The owner should never wonder where information is stored.

---

# Empty States

Empty screens should educate.

Instead of:

"No transactions."

Display:

"Your imported transactions will appear here."

Provide a meaningful next step.

Every empty state should reduce uncertainty.

---

# Error Messages

Every error message must answer three questions:

What happened?

Why did it happen?

What can I do now?

Avoid technical terminology.

Never blame the owner.

---

# Notifications

Notifications exist to inform.

Never to create stress.

Good examples:

"Three transactions need your review."

"Your bank has finished syncing."

Poor examples:

"Warning!"

"You spent too much!"

Tone should remain calm and respectful.

---

# Accessibility

Accessibility is part of the experience.

Every interaction should support:

- keyboard navigation (desktop)
- screen readers
- Dynamic Type
- reduced motion
- sufficient contrast
- large touch targets

Accessibility should never be treated as an optional improvement.

---

# Emotional Outcome

After every interaction, the owner should feel:

"I understand my finances better."

Never:

"I'm not sure what just happened."

---

# UX Success Criteria

The experience is successful when:

- the owner rarely needs documentation
- navigation feels obvious
- financial information becomes easier to understand
- mistakes are easy to recover
- the application creates confidence instead of anxiety

---

# Final Principle

The interface should never compete for attention.

Its purpose is to help the owner focus on what truly matters:

understanding their financial life.
